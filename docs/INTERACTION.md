# 深探交互：详情面板 + 局部展开

> 配套 `DATA-MODEL.md`。那份定「数据怎么存」，这份定「怎么一点点长出来」。
>
> 核心思路：**不做全局深层渲染**。星海默认只到 LOD 1/2，用户点一颗星 → **深探** → 局部冒出新星点和连线，
> 逐级展开。展开状态是**运行时的**，重启即重置回初始深度。

---

## 一、为什么是「深探」而不是「滑杆」

| | 全局滑杆（LOD 0→4） | 点哪展哪（深探） |
|---|---|---|
| 到 LOD 3 | 一次铺十几万点，糊成一片 | 只展开你关心的那一支，几十个点 |
| 性能 | 采样 5000 才画得动 | 精确渲染，不采样 |
| 视觉 | 突然从稀疏变糊 | **冒星点、织网、连线** —— 逐步长成 |
| 心理 | 信息过载 | "伸手拨开一层" |

滑杆仍保留（快速切全局深度），但**主要交互是深探**。

## 三、深探：一次到底，不是逐级

**点一颗星的「深探」= 把它下面所有后代全部激活，一直展到消息层。**

不是"拨开一层"，是"整枝摊开"。

| 深探谁 | 展开内容 | 典型规模 |
|---|---|---|
| **星系（cwd）** | 该项目全部会话 → 全部轮次 → 全部消息 | 几千到几万条 |
| **会话** | 该会话全部轮次 + 全部消息 | **几百到几千条** |
| **轮次** | 该轮全部消息 | 3–20 条 |
| 消息 | 已是最小单位，没有深探 | — |

**唯一的限制是"你点了哪颗"** —— 没点的保持原状，点了的整枝亮起来。

**注意：词不在这条链上。** 词是横向的突触层（第五节），随深探自动浮现并接线。

### 3.1 规模与性能（重要）

单个会话 4000+ 条记录很常见，最大的分片 8.9 MB 压缩。一次摊开这么多，必须：

| 措施 | 做法 |
|---|---|
| **分帧插入** | 每帧最多加 200 个点 → 4000 点约 20 帧（~330ms 内） |
| **布局不重排** | 已有节点 `fx/fy` 钉死，新节点从父节点位置散开 |
| **边分批 reveal** | 和点同步生长，不是瞬间全亮 |
| **超量提示** | 展开 > 8000 条时显示「已展开 4213 条，可能影响流畅度」 |

### 3.2 收起

深探是**幂等可逆**的：**已展开的节点再点一次「深探」= 收起它整个子树**。

按钮文案随状态变：`[深探]` ↔ `[收起]`。

### 3.3 为什么这样反而安全

用户的原话：**「人没那么闲着，一个个手动点」**。

一次点开一个会话是 4000 条，这已经是最重的操作了。而人不会去点 49 次把所有会话都摊开——因为画面会失去信息量。所以：

- 单次操作有上限（一个会话的所有记录）
- 累积状态有自然上限（人懒得点那么多次）
- 真有极端情况，还有「收起」和「重启重置」

**所以不需要"批量深探"这类按钮**——那是多余的复杂度。

## 四、冒星动画：冒星点 · 织网 · 连线

用户描述得很准，三个阶段：

```
t=0ms      父节点轻微"呼吸"一下（scale 1.0 → 1.06 → 1.0）
t=60ms     新星点从父节点位置出生（scale 0，透明度 0）
t=60–420ms 星点沿射线散开 + 放大到目标 scale + 淡入
t=180–600ms 连线从父节点端向新星点"生长"（逐顶点 reveal）
t=420ms+   整个图跑一次很轻的力导向（alpha 0.08，60 tick），微调位置
```

### 技术实现：复用已有的 reveal

`render.js` 里 `REVEAL_GLSL` 本来就是干这个的（开场创世动画），**逐顶点控制边的显现进度**。

深探时只需要：
1. 新增的边 → 单独一批 geometry，`uRevealProgress` 从 0 动画到 1
2. 新增的点 → `aScale` 从 0 动画到 1（`NODE_VERTEX` 里已有 size 通道）
3. 已有的点/边 → 完全不动

**不需要新机制，只是把 reveal 用在增量几何上。**

### 局部布局：不能让整张图重排

深探时最怕的是"点一下，整个星海重新洗牌"。

```js
// 1. 固定所有已有节点
nodes.forEach(n => { n.fx = n.x; n.fy = n.y; });

// 2. 新节点出生在父节点旁边（极近，视觉上像从它身上分出来）
newNodes.forEach(n => {
	n.x = parent.x + rand(-2, 2);
	n.y = parent.y + rand(-2, 2);
});

// 3. 只让新节点自由，跑很轻的一轮
sim.alpha(0.08).tick(60);

// 4. 解除固定
nodes.forEach(n => { n.fx = null; n.fy = null; });
```

`alpha 0.08` 是刻意的：**只做微调，不做重排**。已有节点被 `fx/fy` 钉住，完全不动。

## 五、词：横跨簇的突触

**词不是第 4 层深度，是横向的公共连接器。** 这是整个设计的灵魂——它让孤立的簇连成一张网。

### 5.1 要解决的问题

49 个会话如果不连，星海就是 49 个孤岛。但事实上它们说的是同一件事的不同侧面：
「123 项目」在讨论渲染，「PS 操作」也在讨论渲染。**共享的词就是它们之间的突触。**

### 5.2 三种状态

| 状态 | 条件 | 视觉 |
|---|---|---|
| **休眠** | 没有已展开的记录含它 | 不显示 |
| **簇内** | 只在 1 个簇内出现 ≥2 次 | 簇内小枢纽，同色系，较暗 |
| **桥接** | 跨 ≥2 个簇出现 | **更亮、更大、独立配色**，是跨簇的主干 |

### 5.3 浮现规则（每次深探后重算）

```js
// 1. 收集已展开范围内所有记录的词
const active = new Map();   // word → Set<recordId>
for (const r of expandedRecords) {
	for (const w of r.tokens) {
		if (!active.has(w)) active.set(w, new Set());
		active.get(w).add(r.id);
	}
}

// 2. 出现 ≥2 次 → 浮现为词节点
for (const [w, ids] of active) {
	if (ids.size < 2) continue;

	// 3. 跨几个簇？（按 cwd / session 分簇）
	const clusters = new Set([...ids].map(id => clusterOf(id)));
	const isBridge = clusters.size >= 2;

	ensureWordNode(w, { records: ids, bridge: isBridge });
}
```

**`ensureWordNode` 是幂等的**：
- 节点不存在 → 创建 + 冒星动画 + 连到所有 `ids`
- 已存在 → 只补新增的连线（也带生长动画）

### 5.4 你说的那个场景，落地是这样

> 深探另一大簇的时候，发现有（共同的词），立马连接

```
① 深探「PS 操作」项目的某个轮次 → 冒出 12 条消息
② 重算 active → 发现「渲染」这个词在「123 项目」和「PS 操作」都出现过
③ 「渲染」从「簇内」升级为「桥接」
④ 视觉：词节点变亮变大 + 一条新连线从 PS 那簇的某条消息，长向词节点
         再沿着旧连线连到 123 那簇 —— 两簇瞬间接通
```

**这就是"世界"形成的过程**：每深探一次，网络就多几根突触。

### 5.5 同一簇内也连

同簇的共享词就是**簇内的聚类枢纽**：

```
消息A ──┐
消息B ──┼──▶ 词「three」   （簇内枢纽）
消息C ──┘
```

它的作用是让"散在同一簇里的相似消息"自动靠拢——**布局上词节点会成为引力中心**，把相关消息拉到一起。

### 5.6 视觉区分

| | 簇内枢纽 | 桥接枢纽 |
|---|---|---|
| 大小 | 小（`n * 0.6`） | 大（`n * 1.2`） |
| 亮度 | 暗（`aDim 0.5`） | 亮（`aDim 1.0`） |
| 颜色 | 跟随所属簇 | **独立配色**（暖金 / 青色） |
| 连线 | 普通曲线 | 更亮、更粗 |

### 5.7 会不会太乱

**不会**，因为有阈值：

- 只在**已展开范围**内统计（没深探的不算）
- 词要出现 **≥2 次**才浮现
- 全部展开后最多几千个词节点，但那时用户已经在最深层了
- 提供筛选：`[只看桥接]` 可以把簇内枢纽隐掉，只留跨簇主脉

**关掉的方式**：视图设置里一个开关「词突触」，一关就全部隐没，退回纯净的消息图。

### 5.8 顺带的好处

这个机制让「按词频看」这个视图**自然成立**，不需要单独做——深度钻探的过程本身就是按词频建网。原来的 LOD 4 词星视图可以取消。

## 六、深探状态的生命周期

用户说的规则：

| 规则 | 实现 |
|---|---|
| **点过的留下** | 已深探的节点保持展开 |
| **再点一次收起** | 深探幂等可逆：`[深探]` ↔ `[收起]` |
| **重启重置** | 状态只存 client 内存（React state），**不落盘** |

### 状态形状

```js
expanded = new Set([
	"cwd:D:\\DeepSeek Harness\\123",          // 这个项目整个摊开了
	"session:session-58c36733-…",             // 这个会话整个摊开了
	"turn:session-58c3…#12",                  // 这一轮的消息都摊开了
]);
```

**重启就是 `expanded = new Set()`**，回到 LOD 1 的干净状态。

### 收起 = 反向幂等

```js
function toggle(id) {
	if (expanded.has(id)) {
		// 收起：子树全部移除（带反向动画：缩回父节点 + 淡出）
		for (const child of descendantsOf(id)) {
			if (!expanded.has(parentOf(child))) removeNode(child);
		}
		expanded.delete(id);
	} else {
		// 深探：整枝摊开到消息层
		expanded.add(id);
		spawnAll(descendantsOf(id));
	}
}
```

收起动画是深探的逆过程：**星点缩回父节点、连线反向消隐**，600ms。

### 已加载分片的缓存

深探到 LOD 3 要读 `records/<sessionId>.json`（1–8 MB，几百毫秒）。所以：

```js
const shardCache = new Map();   // sessionId → records[]，只存内存
```

- 第一次展开某会话：读分片（几百 ms，显示 loading）
- 之后同一会话的轮次再深探：**零延迟**（已缓存）
- 缓存上限：比如 10 个会话，LRU 淘汰

## 七、和 LOD 滑杆的关系

两者并存，分工不同：

| | 滑杆（0–4） | 深探 |
|---|---|---|
| 作用域 | 全局 | 单节点 |
| 语义 | "整体看到第几层" | "把这一支拨开" |
| 采样 | LOD 3 全局时按权重采样 | 精确渲染，不采样 |
| 重置 | 随页面 | 随页面 |

**推荐用法**：滑杆定基调（比如 1 或 2），然后靠深探往下钻。

滑杆调到 3 时，只显示**已深探过**的部分 + 采样补齐——不会因为拉滑杆就加载全部。

## 八、性能预算

| 操作 | 预算 |
|---|---|
| 点一颗星出详情（LOD 1/2） | < 30 ms（数据已在内存） |
| 点一颗星出详情（LOD 3，要全文） | 100–300 ms（host 请求） |
| 深探一次（几十个点） | < 150 ms（含动画起始） |
| 读一个会话分片（首次） | 200–800 ms |
| 读同一个（已缓存） | 0 |

## 九、已定 / 待定

### 已定

| 项 | 决定 |
|---|---|
| 详情面板位置 | **跟随星点的浮动卡片** |
| 词的角色 | **横跨簇的突触**，不是独立视图 |
| **深探语义** | **一次到底**——整枝摊开到消息层，不是逐级 |
| 收起 | 再点一次反向回收，带反向动画 |
| 深探状态 | 点过的留下，**重启重置** |
| **深探动画** | **600ms** |
| **桥接词配色** | **青色 `#5eead4`**；簇内词 `#2dd4bf`（更暗） |
| 批量深探按钮 | **不做**（人不会闲到一个个点，也没这个需求） |
| 深探后自动聚焦 | 暂不做 |

**为什么桥接词用青色**：消息星按 kind 配色（user/assistant/tool/compaction），日记是金色。青色在深海背景上最跳，且不与现有任何语义撞色——一眼就能认出"这是跨越两簇的桥"。

### 词突触开关到底是什么（解释）

一个设置项，控制**要不要把词画成节点**：

| 状态 | 画面 |
|---|---|
| **开** | 深探时冒出词节点 + 连线。能看到「PS 操作」和「123 项目」其实在聊同一件事 |
| **关** | 只画消息和消息之间的连线。更干净，但看不到跨簇关联 |

**类比**：开 = 显示"关键词网络"；关 = 只看"对话本身的连线"。

**建议先默认开**，做出来看实际效果再定——因为文档里很难预判它到底会多密。

### 待探讨

1. **深探后自动聚焦** — 用户标记"先不用"。镜头飞向新簇可能打断"观察全貌"。
2. **LOD 3 全文预览长度** — 2000 字够不够，要不要"展开更多"。
3. **词突触开关默认值** — 做出来再定。
